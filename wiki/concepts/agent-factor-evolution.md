# Agent Harness、因子演化与策略演化

更新日期：2026-10-30。状态：第六课教学解释与实际实现；术语例子为学习脚手架，实测结果以[独立报告](../../reports/lesson-06/README.md)为准。来源：[作业与方法摘要](../sources/agent-evolution-lesson-06.md)、[Harness 源码](../../lesson-06/harness.py)、[第五课评价](factor-evaluation.md)。

## 四个对象怎样区分

**Agent** 是阅读当前研究状态、提出下一步实验的决策者。本课由当前 Codex 会话承担。例如看到“反转 IC 为正但换手很高”，提出把调仓从5日改为10日。这是一个待实验的假设，不是原因已经证实。

**Harness** 是约束和运行 Agent 的外壳：定义可用工具、输入契约、记忆、预算、停止条件和证据保存。例如 Agent 不能为了获得高收益把佣金改成0，Harness 会拒绝多余参数。它不等于预测模型，也不保证提案经济上正确。

**因子演化** 改变给股票打分的方法，例如 `-returns(close, 5)` 改成 `-returns(close, 10)`，或组合不同信号排名。若公式不变、只把前50名改成前200名，属于策略层演化。

**策略演化** 改变评分到持仓/交易的规则，例如持仓数、调仓频率或流动性筛选。一个因子可对应多个策略；IC衡量截面关联，账本检验特定资金和成交假设下能否转成收益。

## 一个完整循环

父代是已运行的候选，子代必须保存父代ID与改动理由。子代评价后与父代同目标比较；改善且通过开发门槛才标记 `promoted`。没有改善的子代和失败原因同样进入历史，避免只展示成功路径。每轮排序保留历史精英，不要求后来一代必然优于上一代。

本课外部模型接口为 JSON 输入/输出，公式只允许历史字段及白名单函数。当前会话执行了真实反馈循环；保存的提案可重放。接入外部模型命令的 `auto` 模式可以独立循环，但重放本身不等于模型再次发现。

## 为什么还需要冻结与后续检查

反复看同一段反馈并改公式，会逐渐把偶然波动当成规律。开发目标改善只证明对这个目标更适应。冻结意味着停止改候选，再按事先规则选择并评价后来区间；后续失败也必须保留。

本项目所有历史已可见，所以这些阶段仍是回顾性研究。手续费、开盘深度、公司行为和时点状态缺口也不会因使用Agent消失。完整执行步骤见[系统说明](../../lesson-06/README.md)，验证口径见[日线回测](daily-backtesting-validation.md)。
